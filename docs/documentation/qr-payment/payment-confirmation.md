# Payment Confirmation

After the customer scans and pays successfully, SCB will send a payment confirmation to Merchant's registered URL. All onboarded merchants may provide a payment confirmation endpoint when creating an app.

Do note that there will be no payment confirmation sent if the payment from the customer is not successful.

Once the merchant receives the payment confirmation from SCB, the merchant needs to provide a response to the request with the format outlined in the [response](#response) section below. In the case that there is no response from the merchant, SCB will re-send the payment confirmation to merchant up to 3 times, with an interval of 12 seconds in between attempts.

In the case that SCB does not get a proper response from the merchant after 3 tries, SCB will provide the transaction details to the merchant's registered e-mail.

If a merchant would like to check the transaction status, they can use the inquiry function as provided below:

-   QR 30 : Use [Transaction Inquiry](../../api-reference-index/qr-payments/get-billpayment-transactions.html)
-   QR CS : Use [Transaction Inquiry](../../api-reference-index/qr-payments/get-qrcs-inquiry.html)
-   Alipay+ WeChatPay : Use [Transaction Inquiry](../../api-reference-index/qr-payments/post-ewallets-inquire.html)
-   SCB EASY App Payment : Use [Transaction Inquiry](../../api-reference-index/payment/retrieving-transaction-detail.html)

## Endpoint

-   QR 30 : The endpoint is registered per Biller ID and Reference 3 (Prefix).
-   QR CS : The endpoint is registered per Merchant ID.
-   SCB EASY App payment with bill payment type (BP) : The endpoint is registered per Biller ID and Reference 3 (Prefix).
-   SCB EASY App payment with credit card full amount type (CCFA) : The endpoint is registered per Merchant ID.
-   SCB EASY App Payment with credit card installment payment plan type (CCIPP) : The endpoint is registered per Merchant ID.
-   Alipay+ WeChatPay : The endpoint is registered per Merchant ID.

## Prerequisite

-   The URL must be of type “https” with a valid SSL certificate. We do not support “http” endpoints or “https” with self-signed certificates.
-   Both QR 30 and SCB EASY App payment with bill payment type must be generated with Reference 3 (Prefix).

## Reference Terms

-   QR 30 - Thai QR Code Tag 30
-   QR CS - QR Card Scheme
-   SCB EASY App Payment (BP) - SCB EASY App payment with bill payment type.
-   SCB EASY App Payment (CCFA) - SCB EASY App payment with credit card full amount type.
-   SCB EASY App Payment (CCIPP) - SCB EASY App payment with Credit Card Installment Payment Plan type.

## Response

Merchant will need to provide response to SCB once payment confirmation is receive at merchant endpoint.

| Name | Type | Description |
| :-- | :-- | :-- |
| resCode | String | Fix : 00 |
| resDesc | String | Fix : success |
| transactionId | String | Echo "transactionId" value from Payment Confirmation |
| confirmId | String | Optional |

## Example Response

### QR 30, QR CS, Alipay+, WeChatPay

```json
{
  "resCode": "00",
  "resDesc ": "success",
  "transactionId": "xxx",
  "confirmId" : "xxx"
}
```

## Bank Code

Please check the latest Bank Code from [BOT website](https://www.bot.or.th/Thai/Statistics/DataManagementSystem/Standard/StandardCode/Pages/default.aspx). The detail will be in "รหัสสถาบันการเงิน (Financial Institution Code)" table.
